# PSX

PSX lets PureScript and HTML markup nest in each other. A `.psx` file is a PureScript module where a markup literal can stand wherever an expression can. A `.psxt` file is an HTML document whose `<script type="text/purescript">` is a PureScript module and whose `<template head="f x y">` elements are the bodies of that module's `foreign import f :: T` declarations. Both lower, file by file, to ordinary `.purs`.

- Design: [PSX: mixed markup and PureScript, with tooling](https://claude.ai/artifact/9QSAvYisU4d3JT3hmeYwpu)
- Build plan: [PSX build plan](https://claude.ai/code/artifact/1f9402ce-3ee6-4022-abdb-7e3954c88435), tracked in #1 with one sub-issue per step

## Rules

- **No upstream changes.** Nothing may require a change to the language, purs, spago, the registry or any framework. If a step seems to need one, stop and say so on the issue.
- **Away from the boundary, each language keeps its meaning.** A hole `{expr}` holds an ordinary PureScript expression. No template directives, no capitalised component tags, no attribute spreads; a hole in a start tag (a trait hole, `<div {P.transitionGroup "bounce"} class="list">`) holds exactly one `Attr` and lowers to one element of the attribute array literal, which is never a concatenation. Conditionals and lists are `if`, `case` and `map` in holes.
- **`<` opens markup only at expression start** (after `=`, `(`, `[`, `,`, `->`, `<-`, `then`, `else`, `of`, `in`, a layout opener or an operator). Markup as a function argument must be parenthesised.
- **`key` is the one reserved attribute.** It keys list items and is never rendered. A key belongs to the parent's child list, not to the element: `key` lowers to `B.keyed k node`, a `Tuple Key (Node a)`, and those keyed children are what make the parent a keyed element (Halogen's `HH.keyed`). A trait hole adds one `Attr` to the element and can't change its type, so **a key in a trait hole is not allowed**, unless the framework keys by an attribute of the element itself (Portico's `P.key`). Even then the lowering doesn't track it, so `key` is the portable way to key.
- **Keyedness is the children's type.** Every child hole lowers to `B.children`, and an element function takes plain or keyed children (`Content`); mixing them is a purs error at the hole.
- **Whitespace in text:** trim leading whitespace on every line but the first and trailing on every line but the last, drop empty lines, join with one space. `psx fmt` must never change rendered text.
- **A file's framework is the backend module it imports** (`Portico.Psx`, `Halogen.Psx`, `Screamer.Psx`, `Psx.Static`); the lowering binds alias `B` to it. Zero or several backend imports is an error.
- **A template is an equation, by syntactic transformation.** `<template head="H">…</template>` lowers to `H = […]` with `H` copied as written: the function's name, then PureScript binders, destructuring patterns included (`head="row { id, label }"`, `head="item (Just x)"`). Several templates with one name are that function's equations in order, one per pattern, so they follow one another on the same side of the script and take the same number of binders. Only the first is preceded by the signature from `foreign import f :: T`. Guards are not part of a head.
- **`<style>` is a scoped stylesheet** for the element that contains it; in a `.psxt` file a top-level `<style>` applies to every template's top-level elements. It is extracted to `<File>.css` inside `@scope ([data-psx="<Module>"])`, the element is stamped `data-psx`, and a generated companion module `<Module>.PsxStyle` imports the CSS (`Psx.Lower.Css`).
- **Lowering is line-preserving** where possible and always emits a position map. Generated `.purs` starts with `-- Generated by psx from <file>`.

## Backend signature

```purescript
type Markup a = Array (Node a)
text :: forall a. String -> Node a
-- c is Markup a or Array (Tuple Key (Node a)); keyed children build a keyed element
class Content c a | c -> a
element :: forall c a. Content c a => String -> Array (Attr a) -> c -> Node a
none :: forall a. Markup a
keyed :: forall k a. ToKey k => k -> Node a -> Tuple Key (Node a)
attribute :: forall a. String -> String -> Attr a
class Children c r | c -> r where children :: c -> r  -- r is Markup a, or keyed nodes from keyed literals
root :: forall a. Markup a -> Node a
-- plus one generated function per element (taking any Content), attribute and event in psx-html-data
```

Screamer implements it at `a = Effect Unit`. Each backend ships a `<Framework>.Psx.Conformance` module that uses every name at its expected type.

## Layout

One spago workspace. Toolchain in `packages/` (`psx-html-data`, `psx-cst`, `psx-lower`, `psx-fmt`, `psx-cli`, `psx-language-server`); backends in `backends/` (`psx-portico`, `psx-halogen`, `psx-screamer`, `psx-static`, each a hand-written `<Backend>.Core` plus the module and `Conformance` that `psx gen-backend` writes from `mappings/<framework>.json`); editor grammars in `editors/`; examples in `examples/` (`portico/` as `psx-examples-portico`, `screamer/` as `psx-examples-screamer`); tests in `test/` (`corpus/`, `corpus-runner/` as `psx-corpus`, `suite/` as `psx-suite`, its apps under `suite/apps/<scenario>/<framework>/<variant>/` as `psx-suite-<scenario>-<framework>-<variant>`). Backends never depend on PSX packages, only on their framework. Generated code and goldens are committed.

## Working on a step

- One issue, one PR. The issue's gate is a check in CI; the PR is done when it passes.
- Add corpus cases (`test/corpus/<area>/<case>/input.psx` plus `expected.*`) before the code that makes them pass. `spago run -p psx-corpus -- --accept` rewrites goldens; review the diff.
- Before pushing: `spago build` and `spago test` for every package you touched.
- Implementation language is PureScript on Node. Editor grammars and the VS Code client are the only exceptions.
- If you find the design wrong or ambiguous, comment on the issue rather than inventing a rule.
