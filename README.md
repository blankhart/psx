# Purescript PSX

Design document: [PSX: framework-agnostic markup for PureScript](https://claude.ai/artifact/QVukPHBzPzQVjJG6NvYSTC#0a3beff7-8da5)

## Development

```sh
npm ci                                  # purs and spago, pinned
npx spago build                         # every package in the workspace
npx spago test                          # every package's tests, including the corpus
npx spago run -p psx-corpus -- --accept # rewrite corpus goldens (optionally: area or area/case)
npm run psx -- build examples/react/src # lower .psx files to .purs beside them (after spago build)
npm run psx -- check examples/react/src -- -p psx-examples-react # compile, errors at .psx positions
npm run psx -- fmt src/View.psx         # format in place (--check: report, write nothing)
npm run examples:react                  # React examples and browser smoke tests
npm run psx -- gen-backend              # regenerate every backend and its conformance module from backends/mappings
npm run psx -- explain button           # what psx-html-data knows about an element
```


Each backend's per-name module (`Halogen.Psx`, `React.Basic.Hooks.Psx`, `Psx.Static`) and its `Conformance` module are generated by `psx gen-backend` from `psx-html-data` and the framework's mapping in `backends/mappings/`; the hand-written core is the `.Core` module beside it. Both generated files are committed, and CI checks they regenerate unchanged.


The toolchain lives in `packages/`, the backends in `backends/`, examples in `examples/`, and the tests in `test/`: corpus cases in `test/corpus/<area>/<case>/` (an `input.psx` or `input.psxt` and one `expected.*` golden per stage), the runner in `test/corpus-runner`, the scenario suite in `test/suite`. `CLAUDE.md` has the rules every change follows.

## Framework ownership

PSX includes Halogen, react-basic-hooks, and the framework-free static backend.
Screamer and Portico own their `screamer-psx` and `portico-psx` packages, including
backend mappings, conformance tests, PSX examples, and comparison apps. Their
public imports remain `Screamer.Psx` and `Portico.Psx`; lowering still recognizes them.
PSX does not fetch either framework.

The React backend exports `React.Basic.Hooks.Psx`. Nodes are React JSX, while
event handlers take `Effect Unit`; input handlers take `String -> Effect Unit`.
`style` takes React’s `CSS` value (for example, `{css { color: "red" }}`), as in react-basic-dom.
Use hooks in ordinary PureScript component setup and PSX to render the view.
Run `npm run examples:react` for `.psx` and `.psxt` browser examples.
The scenario suite compares native and PSX implementations for Halogen and React.

Consumers can compile `psx-cli`, `psx-suite`, and `psx-suite-shared` from pinned
Git dependencies. Invoke the compiled CLI with `node scripts/psx.mjs`; run the
compiled suite main with `PSX_SUITE_CONTRACT_ROOT` pointing at the PSX checkout.
Apps and reports stay relative to the consumer workspace.

Run `npm run examples:react` to build and check the examples, then `npm run serve:examples` to bundle and serve their index at http://127.0.0.1:3000/. Set `PORT` to choose another port. Stop with Ctrl+C.

## Application workflow

Use `psx check` for day-to-day builds. It generates the `.purs` files, runs
`spago build --json-errors`, and maps compiler diagnostics back to `.psx` and
`.psxt` source positions. `psx build` only generates files; running `spago build`
separately reports positions in generated PureScript.

For example, after installing the CLI as described below:

```json
{
  "scripts": {
    "build": "node scripts/psx.mjs check src -- -p my-app",
    "format": "node scripts/psx.mjs fmt --purs src",
    "format:check": "node scripts/psx.mjs fmt --purs --check src"
  }
}
```

`build` and `check` warn at the source attribute when an unknown name would
become a string-only `B.attribute`, suggesting a nearby known name. `data-*`,
`aria-*`, and attributes on custom elements remain pass-through attributes.
Use a trait hole for a framework-specific dynamic attribute. Pass-through
attributes retain the portable `String` contract.

`fmt --purs` also runs `purs-tidy` on handwritten `.purs` files. Install
`purs-tidy` as a development dependency and run the command through an npm
script (or put its executable on PATH). Generated files, including style
companions, are identified by their `-- Generated by psx from ` header and
skipped. Use this command instead of a blanket `purs-tidy src/**/*.purs`;
PSX preserves source lines in generated output, which is not tidy-formatted.

## Scoped styles in Node tests and SSR

Style companions import CSS for bundlers. Node needs a loader hook when importing
those modules directly. Create `scripts/css-hooks.mjs`:

```js
export async function load(url, context, nextLoad) {
  if (new URL(url).pathname.endsWith('.css')) {
    return { format: 'module', source: 'export {};', shortCircuit: true };
  }
  return nextLoad(url, context);
}
```

Register it in `scripts/node-setup.mjs`:

```js
import { register } from 'node:module';
register('./css-hooks.mjs', import.meta.url);
```

Preload before importing compiled views (Node 20.6+):

```sh
node --import ./scripts/node-setup.mjs ./output/Test.Main/index.js
```

This ignores CSS in Node; DOM tests still need their DOM setup. For SSR, include
the generated CSS in the browser's assets through your bundler. The hook does
not apply styles or test their appearance. A test entry module must call its
exported `main` if the test runner does not do so itself.

## Using the CLI in another workspace

Install `purescript` and `spago` as development dependencies. In your workspace's
`spago.yaml`, add all five toolchain packages, using the **same commit ref** for
each. Replace `PSX_COMMIT` with the full commit SHA you have selected:

```yaml
workspace:
  packageSet:
    registry: 81.5.0
  extraPackages:
    psx-cst:
      git: https://github.com/blankhart/psx.git
      ref: PSX_COMMIT
      subdir: packages/psx-cst
    psx-html-data:
      git: https://github.com/blankhart/psx.git
      ref: PSX_COMMIT
      subdir: packages/psx-html-data
    psx-lower:
      git: https://github.com/blankhart/psx.git
      ref: PSX_COMMIT
      subdir: packages/psx-lower
    psx-fmt:
      git: https://github.com/blankhart/psx.git
      ref: PSX_COMMIT
      subdir: packages/psx-fmt
    psx-cli:
      git: https://github.com/blankhart/psx.git
      ref: PSX_COMMIT
      subdir: packages/psx-cli
```

Create `tooling/spago.yaml` so Spago compiles the CLI dependency:

```yaml
package:
  name: my-app-tooling
  dependencies:
    - psx-cli
```

Create `tooling/src/Tooling.purs`:

```purescript
module Tooling where

import Psx.Cli as Cli

main = Cli.main
```

Create `scripts/psx.mjs`, relative to the workspace root:

```js
import { main } from '../output/Psx.Cli/index.js';
main();
```

On a fresh clone, run these in order from the workspace root:

```sh
npm ci
npx spago build -p my-app-tooling
node scripts/psx.mjs check src -- -p my-app
```

The app also needs its chosen backend dependency (`psx-halogen`,
`psx-react-basic-hooks`, or `psx-static` from this repository's matching
`backends/<package>` subdirectory, or its framework-owned adapter). The tooling
package isolates bootstrapping from app modules that have not been generated
yet. Commit `spago.lock` and update all PSX refs together. This recipe uses Git
source dependencies; it does not require an npm CLI package or a release tag.

The [PSX language server](packages/psx-language-server/README.md) provides stdio LSP
for `.psx` and `.psxt`, reusing purescript-language-server for compiler features.
Build this checkout, then launch `node packages/psx-language-server/bin/psx-language-server.mjs --stdio`.
